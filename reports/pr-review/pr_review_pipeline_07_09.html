4 As fixtures e a fonte vão ao git com LF; os testes só passam no Windows portabilidade
git ls-files --eol

i/lf w/crlf attr/ retail_analytics/fixtures/rystore/source/orders/dt=2025-06-01/orders.csv
i/lf w/crlf attr/ RYStore-Retail-Dataset/orders.csv

A máquina usa core.autocrlf=true e o repositório não tem .gitattributes, então o git guarda os CSVs com LF e só os devolve com CRLF no Windows. Como o validate_delivery separa as linhas por \r\n, num clone em Linux ou macOS, numa CI ou numa pasta Git do Databricks, cada arquivo vira uma linha só. Aí todas as fixtures dão schema_drift, os 24 testes falham e o load_rystore_to_supabase.py sobe arquivos que a bronze rejeita. A fidelidade de bytes do contrato depende de uma configuração local. O contrato diz CRLF e bytes intactos; nada pode rodar só numa máquina.

Mudança sugerida
+# .gitattributes (novo, na raiz)
+*.csv -text
+# depois: git add --renormalize . e conferir com git ls-files --eol (i/crlf)
autorCorrigido: .gitattributes com *.csv -text e renormalização; o git ls-files --eol agora mostra i/crlf.
